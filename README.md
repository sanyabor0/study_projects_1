# Практическая работа № 1. Конечные автоматы

**Вариант 4**

## 1. Цель работы и постановка задачи

**Цель работы:** реализация и исследование детерминированных и недетерминированных конечных автоматов.

### 1.1. Задание для ДКА

Построить ДКА, допускающий в алфавите `{a, b}` все строки, где остаток от деления на три количества символов `a` больше 1.

Возможные остатки — 0, 1 и 2, поэтому условие выполняется только при остатке 2:

`L₁ = {w ∈ {a, b}* | |w|ₐ mod 3 = 2}`.

Здесь `|w|ₐ` — количество символов `a` в цепочке. Количество символов `b` и их расположение значения не имеют.

### 1.2. Задание для НКА

Построить НКА с количеством состояний, не превышающим 5, для языка:

`L₂ = {aba·bⁿ | n ≥ 0} ∪ {ab·aⁿ | n ≥ 0}`.

Первая часть содержит цепочки с префиксом `aba` и любым количеством следующих `b`. Вторая — цепочки с префиксом `ab` и любым количеством следующих `a`. Степень относится только к последнему символу. При `n = 0` получаются соответственно `aba` и `ab`.

### 1.3. Требования к реализации

Подготовить модели автоматов в формате JFLAP и программную реализацию на Java. Переходы должны выполняться по таблицам, без использования функций обработки строк. Результаты распознавания на одинаковых тестовых цепочках должны совпадать с результатами соответствующего автомата в JFLAP.

## 2. Состояния и таблицы переходов ДКА и НКА

В таблицах начальное состояние отмечено `→`, допускающее — `*`.

### 2.1. Детерминированный конечный автомат

Множество состояний: `Q = {q0, q1, q2}`. Алфавит: `Σ = {a, b}`. Начальное состояние — `q0`, множество допускающих состояний — `F = {q2}`.

Состояние `qi` означает, что число прочитанных символов `a` имеет остаток `i` при делении на 3. При чтении `a` автомат переходит по циклу `q0 → q1 → q2 → q0`, при чтении `b` состояние не меняется.

| Состояние | a | b | Значение |
|-----------|---|---|----------|
| → q0 | q1 | q0 | Остаток 0 |
| q1 | q2 | q1 | Остаток 1 |
| * q2 | q0 | q2 | Остаток 2 |

**Обоснование корректности.** До чтения входа число `a` равно нулю, поэтому автомат находится в `q0`. Каждый символ `a` увеличивает остаток на единицу по модулю 3, а символ `b` его не изменяет. Следовательно, после любого прочитанного префикса состояние точно соответствует остатку числа `a`. Автомат принимает цепочку только в `q2`, то есть ровно при выполнении условия задания.

Модель: [Variant4_DFA.jff](Variant4_DFA.jff).

### 2.2. Недетерминированный конечный автомат

Множество состояний: `Q = {q0, q1, q2, q3, q4}`. Алфавит: `Σ = {a, b}`. Начальное состояние — `q0`, множество допускающих состояний — `F = {q2, q4}`. Использовано пять состояний, что соответствует ограничению задания.

| Состояние | a | b |
|-----------|---|---|
| → q0 | {q1} | ∅ |
| q1 | ∅ | {q2, q3} |
| * q2 | {q2} | ∅ |
| q3 | {q4} | ∅ |
| * q4 | ∅ | {q4} |

Пустое множество `∅` означает отсутствие перехода. ε-переходов нет. Недетерминизм возникает в `q1`: по символу `b` возможны переходы одновременно в `q2` и `q3`.

**Обоснование корректности.** Ветвь `q0 —a→ q1 —b→ q2` с петлёй по `a` в допускающем `q2` распознаёт ровно `ab·aⁿ`, включая `ab` при `n = 0`. Ветвь `q0 —a→ q1 —b→ q3 —a→ q4` с петлёй по `b` в допускающем `q4` распознаёт ровно `aba·bⁿ`, включая `aba` при `n = 0`.

Любой допускающий путь заканчивается в `q2` или `q4`, поэтому принятая цепочка принадлежит одной из этих двух частей языка. Обратно, каждая цепочка из заданного объединения имеет допускающий путь по соответствующей ветви. Следовательно, НКА распознаёт в точности `L₂`.

Модель: [Variant4_NFA.jff](Variant4_NFA.jff).

## 3. Пошаговое распознавание тестовых цепочек

Окончательный ответ определяется после полного чтения цепочки. Ниже приведены последовательности состояний и результаты распознавания.

### 3.1. ДКА — принятие цепочки babab

Последовательность состояний ДКА: `q0 → q0 → q1 → q1 → q2 → q2`. Цепочка содержит два символа `a`, остаток равен 2. После полного чтения достигнуто допускающее `q2`. Результат — **Accept**.

### 3.2. ДКА — отклонение цепочки aaa

Последовательность состояний ДКА: `q0 → q1 → q2 → q0`. Три символа `a` дают остаток 0. Конечное состояние `q0` не допускающее. Результат — **Reject**. Посещение `q2` на промежуточном шаге не означает принятие всей цепочки.

### 3.3. НКА — принятие цепочки ab

Множества состояний: `{q0} → {q1} → {q2, q3}`. Состояние `q2` допускающее, поэтому результат — **Accept**. Это граничный случай `n = 0` для `ab·aⁿ`. Наличие недопускающего `q3` не мешает принятию: НКА достаточно одной допускающей ветви.

### 3.4. НКА — принятие цепочки ababb

| Прочитанный префикс | Активные состояния |
|--------------------|--------------------|
| ε | {q0} |
| a | {q1} |
| ab | {q2, q3} |
| aba | {q2, q4} |
| abab | {q4} |
| ababb | {q4} |

После префикса `aba` активны две допускающие ветви. Следующий `b` оставляет только `q4`, а последний `b` проходит по петле. Результат — **Accept**: цепочка имеет вид `aba·b²`.

### 3.5. НКА — отклонение цепочки abaab

После префикса `aba` активны `q2` и `q4`. Следующий `a` оставляет только `q2`, а перехода из `q2` по последнему `b` нет. Множество состояний становится пустым. Результат — **Reject**.

### 3.6. Сводные результаты проверки

ДКА и НКА распознают разные языки, поэтому их ответы на одну цепочку могут различаться.

| Цепочка | ДКА | НКА |
|---------|-----|-----|
| ε | Reject | Reject |
| a | Reject | Reject |
| aa | Accept | Reject |
| aaa | Reject | Reject |
| aaaaa | Accept | Reject |
| bbb | Reject | Reject |
| babab | Accept | Reject |
| ab | Reject | Accept |
| aba | Accept | Accept |
| abaa | Reject | Accept |
| abaaa | Reject | Accept |
| abab | Accept | Accept |
| ababb | Accept | Accept |
| abb | Reject | Reject |
| abaab | Reject | Reject |
| ababa | Reject | Reject |
| aab | Accept | Reject |
| ba | Reject | Reject |

Для всех 8191 цепочек над `{a, b}` длиной от 0 до 12 результаты Java-реализации совпали с независимой проверкой условий языков и симулятором JFLAP 7.1, загружающим соответствующие JFF-файлы. Этот конечный перебор дополняет доказательства корректности из раздела 2.

Для повторения пошаговой проверки в JFLAP открыть нужный JFF-файл через **File → Open**, выбрать **Input → Step by State**, ввести цепочку и нажимать **Step**. Для проверки набора цепочек используется **Input → Multiple Run**.

## 4. Возможность построения конечных автоматов

Для обеих частей варианта 4 конечные автоматы построены: ДКА содержит три состояния, НКА — пять. Их корректность обоснована в разделе 2. Доказательство невозможности построения для этих языков не требуется.
